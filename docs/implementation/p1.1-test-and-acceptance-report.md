## 3. Adversarial Test Suite Execution Breakdown

Test file: [`tests/security/test_multitenant_isolation.py`](file:///d:/agentic-commerce-gateway/tests/security/test_multitenant_isolation.py)  
Execution command: `pytest tests/security/test_multitenant_isolation.py -v`  
Outcome: **17 PASSED, 1 SKIPPED, 0 FAILED in 8.10s**

### Detailed Results by Attack Category:

1. **Category A: Cross-Tenant Reads (PASS)**
   - `test_cross_tenant_read_members_denied`: Merchant A Owner attempts `GET /api/v1/merchants/MERCH_FOOD/members` $\longrightarrow$ **403 Forbidden** (`"Access denied: You do not possess an active membership"`).
   - `test_cross_tenant_switch_unauthorized_denied`: Merchant A Owner attempts `POST /api/v1/merchants/MERCH_FOOD/switch` $\longrightarrow$ **403 Forbidden**.

2. **Category B: Cross-Tenant Writes (PASS)**
   - `test_cross_tenant_create_invitation_denied`: Merchant A attempts `POST /api/v1/merchants/MERCH_FOOD/invitations` $\longrightarrow$ **403 Forbidden**.
   - `test_cross_tenant_modify_member_denied`: Merchant A attempts `PATCH /api/v1/merchants/MERCH_FOOD/members/{id}` $\longrightarrow$ **403 Forbidden**.

3. **Category C: Payload Spoofing / Parameter Tampering (PASS)**
   - `test_payload_spoofing_does_not_override_server_tenant_context`: Inbound request injects spoofed header `X-Merchant-ID: MERCH_FOOD`. Endpoint resolves strictly to `MERCH_ELEC` based on verified JWT. Spoofed parameter is completely ignored.

4. **Category D: Role Escalation & Invariant Protection (PASS)**
   - `test_staff_cannot_invite_members`: STAFF attempts to issue invitation $\longrightarrow$ **403 Forbidden** (`"Insufficient permissions"`).
   - `test_admin_cannot_grant_or_invite_owner`: ADMIN attempts to invite a new member with role `OWNER` $\longrightarrow$ **403 Forbidden** (`"Privilege escalation prevented"`).
   - `test_cannot_demote_or_disable_final_active_owner`: Attempting to demote or suspend the final active OWNER of an organization $\longrightarrow$ **409 Conflict** (`"Cannot demote, suspend, or remove the final active OWNER"`).

5. **Category E: Authentication Domain Separation (PASS)**
   - `test_merchant_employee_token_rejected_at_buyer_mcp_endpoint`: Merchant employee token submitted to `/mcp` $\longrightarrow$ **401 Unauthorized** (rejected by `McpAuthMiddleware`).
   - `test_buyer_oauth_token_rejected_at_merchant_api`: Buyer OAuth token submitted to `/api/v1/merchants/me` $\longrightarrow$ **401 Unauthorized** (`"Invalid authentication token: Signature verification failed"`).
   - `test_invalid_token_signature_rejected`: Token signed with arbitrary HMAC secret $\longrightarrow$ **401 Unauthorized**.

6. **Category F: Immediate Session Revocation (PASS)**
   - `test_immediate_session_revocation_on_logout`: Employee authenticates -> logs out via `/api/v1/auth/logout` -> previous token immediately rejected on next request with **401 Unauthorized** (`"Session has been revoked or expired"`).
   - `test_immediate_token_rejection_on_account_deactivation`: Deactivating employee account in DB -> immediate **401 Unauthorized**.

7. **Category G: Connection Pool Concurrency Isolation (PASS)**
   - `test_connection_pool_tenant_concurrency_isolation`: 50 concurrent requests executed across 10 thread workers alternating between Merchant A and Merchant B. Asserted 0% context leakage; 100% of responses returned the exact expected tenant data.

8. **Category H: PostgreSQL Row-Level Security (NOT RUN)**
   - `test_postgresql_rls_status`: Evaluates real PostgreSQL RLS when `DATABASE_URL` points to a live PostgreSQL instance. Because PostgreSQL is not installed locally on this host (port 5432 closed), this test is cleanly reported as `SKIPPED: NOT RUN — PostgreSQL service unavailable in local workstation environment`.

9. **Category I: Legacy P0 Compatibility & Multi-Tenant Lifecycle (PASS)**
   - `test_merch_elec_preserved_and_seeded`: `MERCH_ELEC` confirmed active and seeded on startup.
   - `test_merchant_registration_and_switching_flow`: Verified full user journey: register org 1 -> create org 2 -> list orgs -> switch context to org 2.
   - `test_invitation_lifecycle_flow`: Verified full invitation journey: invite as manager -> accept with password -> member active -> burned token cannot be reused.
