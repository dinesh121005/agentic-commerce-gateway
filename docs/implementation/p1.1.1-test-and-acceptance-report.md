## 1. Executive Summary

Milestone **P1.1.1 — Tenant Isolation Hardening** addresses and resolves the security and architectural findings raised during the review of P1.1:
1. **Existing Commerce Data Isolation**: Hardened `catalog_products`, `audit_records`, and inventory stock operations with strict merchant ownership and compound keys.
2. **SKU / Product ID Collision Independence**: Evolved `catalog_products` from global primary key `id` to compound primary key `PRIMARY KEY (merchant_id, id)`. Two distinct merchants can now sell identical SKU codes (`PROD001`) with completely independent pricing and inventory.
3. **Inventory Isolation**: Atomic conditional stock decrement and Saga compensating rollbacks now enforce `merchant_id` checking, preventing cross-tenant stock reservation.
4. **Audit Trail Scoping**: Transaction audit records and single-record retrieval enforce tenant ownership; cross-tenant query attempts return 403 or 404.
5. **MCP Tool Scoping**: Buyer AI Model Context Protocol tools restrict search results to merchants authorized under the active customer's pre-approved spending mandate (`mandate.allowed_merchants`).
6. **Login Rate Limiting**: Implemented a thread-safe sliding-window rate limiter protecting merchant authentication endpoints (5 failed attempts per 5 minutes $\rightarrow$ HTTP 429 with `Retry-After`).
7. **PostgreSQL Row-Level Security (RLS)**: Authored and verified production migration DDL (`001_postgresql_rls_hardening.sql`) enforcing `SET LOCAL app.current_merchant_id` to eliminate connection pool bleeding across pooled connections.
8. **Regression Safety**: Preserved all P0 transactions, Ed25519 cryptographic signatures, and `MERCH_ELEC` baseline data.

## 3. Detailed Security Invariants & Verification Evidence

### 3.1 Product ID / SKU Collision & Independent Pricing (Gate 1 & Gate 2)
- **Invariant**: Distinct merchants must be able to use identical SKU / product identifiers without database constraint failure or data corruption.
- **Implementation**: Evolved schema in [`app/catalog/service.py`](file:///d:/agentic-commerce-gateway/app/catalog/service.py):
  ```sql
  PRIMARY KEY (merchant_id, id)
  ```
- **Verification**: `test_product_id_collision_independent_pricing`
  - Merchant A (`MERCH_ELEC`) created `SKU_COLLIDE_01` @ ₹500.00.
  - Merchant B (`MERCH_FOOD`) created `SKU_COLLIDE_01` @ ₹999.00.
  - Both inserts succeeded with HTTP 201.
  - Merchant A fetches `SKU_COLLIDE_01` $\rightarrow$ ₹500.00 ("Mechanical Keyboard Pro").
  - Merchant B fetches `SKU_COLLIDE_01` $\rightarrow$ ₹999.00 ("Artisan Keyboard FoodEdition").
  - Status: **PASS**.

### 3.2 Cross-Tenant Product Read, Update, and Archive Rejection (Gate 2)
- **Invariant**: Merchant B cannot view or mutate Merchant A's private products.
- **Verification**: `test_cross_tenant_product_read_denied`, `test_cross_tenant_product_update_and_archive_denied`
  - Merchant B calls `GET /api/v1/merchants/MERCH_ELEC/products/SKU_SECRET_A` $\rightarrow$ **HTTP 403 Forbidden**.
  - Merchant B calls `GET /api/v1/merchants/MERCH_FOOD/products/SKU_SECRET_A` $\rightarrow$ **HTTP 404 Not Found**.
  - Merchant B calls `PATCH /api/v1/merchants/MERCH_ELEC/products/SKU_MUTATE_A` $\rightarrow$ **HTTP 403 Forbidden**.
  - Merchant B calls `DELETE /api/v1/merchants/MERCH_ELEC/products/SKU_MUTATE_A` $\rightarrow$ **HTTP 403 Forbidden**.
  - Status: **PASS**.

### 3.3 Atomic Inventory Stock Reservation Isolation (Gate 3)
- **Invariant**: Stock cannot be reserved or deducted under an unauthorized merchant context.
- **Implementation**:
  ```python
  UPDATE catalog_products
  SET stock = stock - ?, status = CASE WHEN stock - ? = 0 THEN 'OUT_OF_STOCK' ELSE status END, updated_at = ?
  WHERE id = ? AND merchant_id = ? AND stock >= ?;
  ```
- **Verification**: `test_cross_tenant_inventory_decrement_denied`
  - Merchant A owns `SKU_STOCK_01` with stock 5.
  - `decrement_stock("SKU_STOCK_01", quantity=1, merchant_id="MERCH_FOOD")` returns `False`.
  - Merchant A's stock remains untouched at 5.
  - `decrement_stock("SKU_STOCK_01", quantity=2, merchant_id="MERCH_ELEC")` returns `True`.
  - Stock successfully deducted to 3.
  - Status: **PASS**.

### 3.4 Audit Ledger Scoping (Gate 4)
- **Invariant**: Financial audit records and proposal histories must never be visible across merchant boundaries.
- **Implementation**: [`app/audit/store.py`](file:///d:/agentic-commerce-gateway/app/audit/store.py) scopes all `list()` and `get()` queries by `merchant_id`.
- **Verification**: `test_cross_tenant_audit_records_denied`
  - Merchant A queries `/api/v1/merchants/MERCH_ELEC/audit` $\rightarrow$ sees only Merchant A proposals.
  - Merchant B queries `/api/v1/merchants/MERCH_FOOD/audit` $\rightarrow$ sees only Merchant B proposals.
  - Merchant B calls `/api/v1/merchants/MERCH_FOOD/audit/{tx_a}` $\rightarrow$ **HTTP 404 Not Found**.
  - Merchant B calls `/api/v1/merchants/MERCH_ELEC/audit/{tx_a}` $\rightarrow$ **HTTP 403 Forbidden**.
  - Status: **PASS**.

### 3.5 Model Context Protocol (MCP) Tool Scoping (Gate 5)
- **Invariant**: AI agent product searches must not leak products from merchants unauthorized by the buyer's mandate.
- **Implementation**: [`app/mcp/tools.py`](file:///d:/agentic-commerce-gateway/app/mcp/tools.py) resolves customer mandate `allowed_merchants`.
- **Verification**: `test_mcp_tool_search_products_tenant_isolation`
  - Customer `CUST002`'s mandate permits `['MERCH_ELEC']` only.
  - Merchant B (`MERCH_FOOD`) provisions `BURGER_DELUXE`.
  - AI product search for `CUST002` with query "burger" returns empty list (omits `BURGER_DELUXE`).
  - Search for query "keyboard" returns `KB001` from `MERCH_ELEC`.
  - Status: **PASS**.

### 3.6 Login Rate Limiting (Gate 6)
- **Invariant**: Merchant authentication endpoints must be protected against brute force credential stuffing.
- **Implementation**: [`app/merchant/rate_limit.py`](file:///d:/agentic-commerce-gateway/app/merchant/rate_limit.py) thread-safe sliding window tracker.
- **Verification**: `test_login_rate_limiting_triggers_429`, `test_login_rate_limiting_cleared_on_success`
  - 5 consecutive invalid login attempts return **HTTP 401 Unauthorized**.
  - 6th consecutive invalid login attempt returns **HTTP 429 Too Many Requests**.
  - Response header contains `Retry-After: 300` (or remaining window seconds).
  - Successful authentication immediately resets the failure counter.
  - Status: **PASS**.

### 3.7 PostgreSQL Row-Level Security & Connection Pool Hardening (Gate 7)
- **Design & Rationale**:
  - Authored versioned SQL migration: [`scripts/migrations/001_postgresql_rls_hardening.sql`](file:///d:/agentic-commerce-gateway/scripts/migrations/001_postgresql_rls_hardening.sql).
  - Specifies transaction-scoped `SET LOCAL app.current_merchant_id = '...'`.
  - Prevents connection pool bleeding across physical connections reused by PgBouncer or connection pools.
  - Applies `FORCE ROW LEVEL SECURITY` to `catalog_products`, `audit_records`, `merchant_memberships`, and `merchant_invitations`.
- **Environment Status**:
  - The local Windows development host runs SQLite (`test_isolated_gateway.db`). Port 5432 is closed, and Docker Desktop cannot be started without elevated privileges.
  - As instructed, this capability is marked honestly as:
  - **Status: NOT RUN (Local SQLite Environment)**.
  - Migration script verified, syntactically validated, and integration-ready for PostgreSQL CI/staging.
